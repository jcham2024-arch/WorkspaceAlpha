# Harness-Adapter Contract

**contract_version: 1.0.0**

This document specifies the file-based integration surface between the WorkspaceAlpha
baselayer and any harness that consumes it. The contract is versioned using semver;
breaking changes require a major version bump.

## Read Order

A harness must consume workspace artifacts in this order:

1. **`AGENTS.md`** — Agent router entry point (≤150 lines). Read first for orientation.
2. **`.context/manifest.json`** — Generated routing table. Contains node IDs, byte ranges,
   SHA-256 hashes, and edges. Defines the DAG structure.
3. **`.harness/skills/`** — Currently-used skill set, provisioned per active profile via
   `python3 .harness/sync_active.py --profile <name>`.

Do NOT read `docs/` directly. Do NOT `grep` for content in docs. Hydrate sections
only by `byte_range` from `manifest.json`.

## Invariants

A harness may assume the following are always true:

| Invariant | Description |
|-----------|-------------|
| Manifest is acyclic | No cycles in the DAG (validated by `build.py` and `validate.py`) |
| Node IDs are unique | No duplicate IDs in `manifest.json` |
| Byte ranges are valid | `byte_range[0]` < `byte_range[1]` and within file bounds |
| SHA-256 hashes match | Each node's hash matches the content at its byte range |
| Active skills ⊆ provisioned skills | Every skill in `.harness/skills/` exists in `.agent/skills/` |
| Contract version present | `manifest.json` contains `contract_version` field |
| AGENTS.md ≤ 150 lines | Router stays under ~15% of context budget |

## What a Harness May Assume

- `manifest.json` is regenerated by `python3 .wiki/build.py` after any docs change
- `.context/graph.json` is the source of truth; manifest is derived
- `.wiki/index.html` is the human-readable rendering of the same graph
- Skill frontmatter in `.agent/skills/<name>/SKILL.md` is authoritative for skill metadata
- Profile frontmatter in `.agent/profiles/<name>.md` determines which skills are active
- `validate.py` passes on every commit (pre-commit hook)

## What a Harness Must NOT Assume

- **Do not grep docs/ directly.** Use manifest.json byte ranges instead.
- **Do not read `.wiki/index.html` for programmatic decisions.** It's for humans.
- **Do not assume skill files have a particular structure beyond frontmatter.** Body format varies.
- **Do not assume `.agent/` is untracked.** It may or may not be in git depending on deployment model.
- **Do not assume network access.** All tools are stdlib-only; no external API calls.
- **Do not assume `.env` contains real keys.** It's gitignored and may be empty.

## Contract Version

- Current: `1.0.0`
- Semver rules: major = breaking change to read order or invariants; minor = new optional fields; patch = documentation fixes
- The `contract_version` field is present in `.context/manifest.json`

## Golden Files

Golden copies of `AGENTS.md` and `.context/manifest.json` are stored in
`tests/fixtures/golden/`. Any deliberate change to these files requires updating
the golden copies via the test suite.

## Reference Adapter

A minimal reference adapter exists at `tools/reference_adapter.py` demonstrating
end-to-end consumption: reads AGENTS.md → manifest.json → active skills → validates invariants.
